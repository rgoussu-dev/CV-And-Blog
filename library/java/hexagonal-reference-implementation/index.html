    • -rw-r--r-- Hexagonal reference implementation — the layout Concept 2026-08-09

      The house layout for a hexagonal monolith/microservice in Java — Maven multi-module, application/domain/infrastructure trisection, one deployment unit per primary adapter.

    • -rw-r--r-- Application layer — primary adapters as deployment units Concept 2026-08-09

      Per user-side adapter, an implementation module plus an API module where the contract is real — each mapping to a single unit of deployment — and the optional configurator that harbors the wiring.

    • -rw-r--r-- Domain layer — contract & implementation Concept 2026-08-09

      Two modules — domain-api with the surface API of the domain (ports, command DTOs) and domain-core with the actual implementation — and the rules for what crosses that line.

    • -rw-r--r-- Infrastructure layer — secondary adapters & the granularity debate Concept 2026-08-09

      Folder or single module — infrastructure granularity is decided ad-hoc per context; the forcing question is which deployment units need which driven adapters, with a commons module harboring the ubiquitous ports.

    • -rw-r--r-- Deployment & IaC — containers beside their unit, stacks in one folder Concept 2026-08-09

      Containerisation definitions live alongside the deployment unit they belong to; a deployment folder holds the infrastructure-as-code (OpenTofu or the like) defining the services.
