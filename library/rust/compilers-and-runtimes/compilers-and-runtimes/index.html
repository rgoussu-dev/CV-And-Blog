    Rust compilers & the language definition

    # rustc as the single implementation — with gccrs and mrustc as the outliers and the WASM targets — and the spec situation: the Rust Reference versus the Ferrocene FLS.

    Conceptsaved 2026-08-09 #rust#compilers#rustc#specification#wasm

    Overview

    Java has a specification with several competing runtimes (JVM implementations compared); Go has a short spec and one utterly dominant implementation (Go compilers & runtimes compared); Rust goes one further: for most of its life the implementation was the definition. rustc is the only complete compiler, and until recently there was no specification at all — just the Rust Reference, explicitly non-normative. The outliers (gccrs, mrustc) exist to reimplement rustc's behaviour, not to compete with it, and the push toward a real specification came less from portability than from safety-critical certification — the Ferrocene FLS, now adopted by the project as the seed of an official spec.

    Key points

    • rustc is the single implementation: LLVM-backed, self-hosted, shipped every six weeks by the project. "What does Rust do here?" is answered by what rustc does — there is no TCK, and conformance means matching rustc.
    • No language runtime to implement: no GC, no scheduler, no VM — a "Rust runtime" is just libstd over the OS. The runtime question Java and Go answer in the platform, Rust pushes to libraries — which is why async runtimes is where that question reappears.
    • gccrs: a from-scratch Rust front-end inside GCC — motivated by GCC-only platforms, distro bootstrapping, and GCC's plugin/analysis ecosystem. Years in, still incomplete (no stable borrow checker story; targets older editions first); explicitly aims to match rustc, not fork the language.
    • mrustc: a C++ Rust compiler that skips borrow checking entirely (it assumes the input is valid Rust) — built to break the trusting-trust bootstrap chain: mrustc compiles an old rustc from source, which then compiles forward.
    • Ferrocene: not an alternative compiler but a qualified rustc — the same source, packaged and certified (ISO 26262/IEC 61508) for automotive/industrial use by Ferrous Systems. Proof that the single-implementation strategy can reach regulated industries.
    • Codegen backends diversify below the front-end: LLVM is production; Cranelift is an in-tree alternative for faster debug builds; rustc_codegen_gcc reuses rustc's front-end with GCC codegen (a lighter path to GCC platforms than gccrs).
    • WASM is a first-class target family: wasm32-unknown-unknown (browser, with wasm-bindgen/wasm-pack generating the JS glue) and wasm32-wasip1/wasip2 (server-side WASI runtimes). No bundled runtime means small modules by default — the niche TinyGo fights for, Rust gets for free.

    Details

    The spec situation — the Reference vs the Ferrocene FLS

    Two documents describe the language, with different ambitions:

    • The Rust Reference (doc.rust-lang.org/reference) — the project's own description of syntax and semantics. Informal, maintained alongside the compiler, explicitly not normative: it documents rustc, trailing it where undocumented behaviour exists. For daily "what are the rules?" questions it is the right document.
    • The Ferrocene Language Specification (FLS) — written by Ferrous Systems because certification authorities require a specification to qualify a compiler against. Structured like a real language standard (numbered paragraphs, defined terms), it describes the language as implemented by a specific rustc version. In 2025 Ferrous Systems donated the FLS to the Rust Project, and the project's specification team (t-spec, chartered by RFC 3355) adopted it as the basis for the official Rust specification — merging the Reference's coverage with the FLS's rigor is the ongoing work.

    The contrast with the neighbours: Java's spec is contractual (TCK-enforced, multiple independent implementations), Go's is a deliberately short readable document, and Rust's is being reverse-engineered from the implementation under pressure from safety-critical adoption. Until it lands, the practical rule stands: rustc defines Rust; the editions system defines which Rust your crate speaks. Saved reference: The Rust Reference & the Ferrocene FLS.

    Comparison

    Implementation What it is Completeness Sweet spot
    rustc (LLVM) The reference and only complete compiler Defines the language Everything
    rustc + Cranelift Alternative in-tree codegen backend Complete front-end; codegen for dev Faster debug builds
    rustc_codegen_gcc rustc front-end, GCC codegen Front-end complete; backend maturing GCC-only platforms
    Ferrocene Qualified rustc distribution Identical to its rustc base Safety-critical (ISO 26262)
    gccrs Independent GCC front-end Incomplete; trails by years Bootstrapping, GCC purism — future
    mrustc C++ bootstrap compiler, no borrow check Enough to build old rustcs Breaking the bootstrap chain

    WASM targets

    wasm32-unknown-unknown produces bare WASM for the browser; wasm-bindgen generates the JS/DOM interop layer and wasm-pack packages it for npm. wasm32-wasip1 (and the component-model wasip2) target server-side runtimes — Wasmtime, Wasmer, wazero. Because Rust ships no runtime, modules start in the tens of KB — against the megabytes of Go's stock WASM output — which is why Rust dominates WASM plugin systems, proxy filters (Envoy), and smart-contract platforms.
